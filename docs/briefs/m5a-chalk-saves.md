## Part 1: exact inputs
A ghost is a second skater stepped with recorded inputs in the same world at the same ticks (see "the ghost contract" test in `tests/sim/determinism.test.ts`). For recordings to be compact and exact, `Game.step` must quantise the steer it passes to the sim to 255 levels: `steerQ = round(clamp(steer, -1, 1) * 127)`, sim gets `steerQ / 127`. Do this always, recording or not, so behaviour never depends on whether a recording is running. Existing tests must still pass (if a sim test that goes through `Game` changes numerically, that is expected; tests that drive `Sim` directly are unaffected).

## Part 2: chalk lines (`src/sim/game/chalk.ts`)
```ts
export interface ChalkLine {
  v: 1;
  id: string;            // stable hash of the content (so re-importing the same code is a no-op)
  name: string;          // up to 24 chars
  startDayTick: number;  // 0..DAY_TICKS-1, the time of day the recording started
  x: number; z: number; heading: number; speed: number;   // canonical start (see below)
  inputs: Uint8Array;    // run-length encoded frames (see below)
  ticks: number;         // length of the recording
  endX: number; endY: number; endZ: number;               // where the recording stopped: centre of the finish zone
  bestTicks: number;     // best player time in a race, or 0 if never beaten/finished
}
export const CHALK_END_RADIUS = 6;      // metres (also needs |dy| < 4)
export const CHALK_MAX_TICKS = 4 * 60 * 60;
export const CHALK_MIN_TICKS = 5 * 60;
export const CHALK_COUNTDOWN_TICKS = 3 * 60;
export const CHALK_MAX_LINES = 20;
```
- **Canonical start.** A recording (and a race) starts from a canonical state so the code only needs position, heading and speed: `placePlayer(world, player, x, z, heading)` then `player.speed = speed`. Recording can only start while the skater is in GROUND mode, not bailing or hitched, and the game applies that canonicalisation to the live skater at the moment recording starts (cooldowns and steer smoothing reset; position, heading and speed kept).
- **Frames.** One byte of steer (`steerQ + 127`, 0..254) and one of flags (bit 0 hold, bit 1 hop) per tick, run-length encoded as (steerByte, flags, runLength 1..255) triples. A recording stops on command, at `CHALK_MAX_TICKS`, or is aborted by a bail in water. Shorter than `CHALK_MIN_TICKS` is discarded with a reason.
- **Share code.** `encodeChalk(line): string` and `decodeChalk(code): ChalkLine | { error: string }`. Format: the prefix `SK1-`, then base64url (no padding) of a binary packing: version byte, name (length byte + UTF-8), startDayTick u16, x/z/heading/speed as float64 (exact bits; do not quantise), endX/endY/endZ as float32, ticks u16, input byte count u16, input bytes, then a CRC-32 of everything before it. Decoding rejects a bad prefix, bad base64, truncation, CRC mismatch, an unknown version, a run total that does not equal `ticks`, ticks out of range, and non-finite numbers, each with a distinct short error string. Whitespace and line breaks inside a pasted code are ignored. No `atob/btoa/TextEncoder` (not available in the sim's lint environment): write base64url and UTF-8 by hand in the sim layer. Typical codes should stay under about 1.5 kB for a 2-minute route; report the size you measure.
- **Racing.** `Game` commands (plain methods, the only way UI changes game state): `chalkStartRecording()`, `chalkStopRecording(name)`, `chalkCancel()`, `chalkStartRace(id)`, `chalkAbortRace()`, `chalkImport(code)`, `chalkDelete(id)`, `chalkRename(id, name)`. Each returns `{ ok: true } | { ok: false; reason: string }`.
  - Starting a race moves the clock forward to the next time the day tick equals `startDayTick - CHALK_COUNTDOWN_TICKS` (never backwards; `sim.tick` is writable), places the skater at the canonical start, and creates the ghost: a `SimCtx` sharing the world with its own `PlayerState` at the same canonical start.
  - Countdown: for `CHALK_COUNTDOWN_TICKS` ticks the clock advances with `sim.tickOnly()` and neither skater steps (rides keep moving). Then both go: each `Game.step` steps the sim with the player's input and the ghost with the next recorded frame (`ghost.tick = sim.tick` before stepping it). When the recording runs out the ghost stays where it stopped.
  - The player finishes on entering the finish zone (plan distance to (endX, endZ) under `CHALK_END_RADIUS` and |y − endY| < 4). They win if their ticks are less than or equal to the line's `ticks`; `bestTicks` updates when they finish faster than before. The race also ends (lost) 20 s after the ghost finishes, or on abort. While racing, line-map progress and other reducers keep working normally.
  - `GameEvent` additions: `chalkRecordStart`, `chalkRecordStop { id, ticks }`, `chalkRecordDiscard { reason }`, `chalkCountdown { secondsLeft }` (3, 2, 1), `chalkGo`, `chalkFinish { id, ticks, ghostTicks, won, best }`, `chalkAbort`.
  - State the UI/renderer reads: `game.chalk` with `lines: ChalkLine[]`, `mode: 'idle' | 'recording' | 'countdown' | 'racing'`, `elapsedTicks`, `ghost: SimCtx | null` plus the ghost's previous position (for interpolation) and whether it has finished, `activeId`.
- A helper `chalkPath(world, line): Float32Array` that replays a line headlessly from its canonical start and returns the skater's xyz every 6 ticks (for drawing the chalk trail and for tests). Cache per line id.

## Part 3: saves (`src/sim/game/save.ts` pure, `src/app/save.ts` glue)
- Extend the reducer interface: `interface GameReducer { readonly key: string; step(game: Game): void; exportState?(): unknown; importState?(data: unknown): void }`. Progress and chalk implement export/import (chalk lines are stored as their share codes plus `bestTicks`). Later reducers (errands, conductors, secrets) will plug into the same mechanism without touching the save code.
- `SaveData`: `{ version: 1, savedAtTick: number, player: { x, z, heading, dayTick }, settings: { music: number, sfx: number, haptics: boolean, hints: boolean }, reducers: Record<string, unknown> }`. `exportSave(game, settings)`, `importSave(game, data)`: restores reducer state, puts the skater at rest at the saved position (use the sim's safe position: `player.safeX/safeZ/safeHeading`, never a point over water or inside a solid) and the clock at the saved day tick. `migrate(raw: unknown): SaveData | null` validates shape and upgrades older versions through a chain of per-version functions (only v1 exists; structure it so v2 is one more function); anything unrecognisable returns null rather than throwing. A reducer whose saved data is malformed starts fresh without affecting the others.
- `src/app/save.ts`: load on boot from `localStorage['skitch.save.v1']` (try/catch everywhere: private mode and quota errors must not break the game); keep the previous good save under `'skitch.save.bak'` before overwriting; autosave on any of these game events: `segmentInked`, `lineComplete`, `chalkRecordStop`, `chalkFinish`, and every 15 s of play, and on `visibilitychange` to hidden / `pagehide`. `?e2e` runs must not read or write storage unless the URL has `save` (add nothing to `params.ts`; read `new URLSearchParams(location.search).has('save')` in `src/app/save.ts`), so the existing routes stay deterministic. Expose `resetSave()` for the future settings screen.
